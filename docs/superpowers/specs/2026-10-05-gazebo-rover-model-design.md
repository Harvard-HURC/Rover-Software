# Gazebo rover model — design

Date: 2026-10-05
Status: implemented 2026-10-05 (revised after prototyping: DART + C++ differential plugin
instead of mimic joints)

## Goal

A generic Gazebo (Harmonic, gz-sim 8) model of our rover so we can drive it
in simulation before the mechanical numbers exist:

- Rectangular chassis.
- Rocker suspension, 4 wheels: one rocker per side carrying a front and a rear
  wheel, the two rockers joined by a differential. (A rocker-bogie without the
  bogies.)
- Tank / skid-steer drive: the wheels never steer; the two left wheels share
  one speed and the two right wheels another.

The real rover's design changed from swerve to tank on 2026-10-05; the swerve
driver in `driver/` is superseded, but its placeholder geometry in
`driver/include/rover_driver/config.hpp` is the best numbers we have, so the
model reuses them.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Physics engine | DART (gz-physics dartsim plugin, the Gazebo default) | Only engine here with anisotropic tire friction, which skid-steer turning needs (see "Why not mimic joints"). |
| Differential | Small C++ system plugin `RockerDifferential` | DART has no mimic joints; a compiled plugin works in Gazebo's in-process Python test fixture (a Python plugin crashes it). |
| Model format | SDF 1.11, generated by a Python script from one parameter block | Gazebo-native; dimensions in one place; inertias computed. `xacro` is not in the env. |
| Drive | gz `DiffDrive` system with two joints per side | Built in; tank drive is a diff drive with more wheels. |
| ROS 2 | `ros_gz_bridge` with a YAML config | Already a pixi dependency. ros2_control deliberately deferred. |
| Tests | Python `unittest`: generator unit tests + headless in-process physics tests via `gz.sim8` / `gz.transport13` | Bindings already in the env; no GUI needed. |

## Why not mimic joints

The first design coupled the rockers with an SDF `<mimic>` joint
(`q_R = −q_L`). Prototyping in this env (gz-sim 8.10, gz-physics 7,
DART 6.19, sdformat 14) showed:

- Mimic constraints are implemented **only** by the Bullet-Featherstone engine;
  DART ignores them.
- Under Bullet the mimic differential itself is excellent: with a 10 cm block
  under the front-left wheel the rockers settle at −0.0558 / +0.0558 rad
  (geometry predicts ±0.0553), and the coupling is bilateral — pushing either
  rocker moves both equally (a gear constraint, not a one-sided motor).
- But under Bullet **the rover cannot turn in place**: commanding 0.5 rad/s for
  4 s yields zero yaw while the wheels spin at full speed. Bullet's box
  friction keeps full lateral grip on a longitudinally sliding wheel, and with
  half-wheelbase (0.45 m) > half-track (0.40 m) the lateral scrub moment always
  wins. Bullet ignores the usual remedy (lower lateral μ via `fdir1`/`mu2`),
  ignores joint damping, and applies the SDF default torsional friction
  coefficient (1.0) as spinning friction that also blocks yaw.
- DART honors `fdir1`/`mu2`: lateral μ 0.5, longitudinal μ 1.0 turns the rover
  1.74 rad of a commanded 2.0 rad in 4 s with no drift.

So: DART for friction, and the differential as a plugin. If a future Gazebo
adds mimic support to DART, the plugin can be swapped for a `<mimic>` tag.

## Out of scope

Cameras, lidar, GPS; an RViz robot model (needs a URDF and
`robot_state_publisher`); ros2_control; terrain meshes; motor models beyond a
torque limit; slip-ratio tire models.

## Conventions

- Model origin = `base_link` frame = the driver's body frame: ROS REP-103
  (x forward, y left, z up), on the ground midway between the four wheel
  contact points when the rockers are at zero.
- Rocker angle: rotation of the rocker relative to the body about +y
  (right-hand rule: positive lowers the rocker's front), same as the driver.
- Wheel angle: rotation about the axle (+y); positive rolls the rover forward.
- SI units, radians.

## Parameters

All live in the `Params` dataclass at the top of `sim/gen_model.py`.
Defaults:

| Parameter | Default | Source |
|---|---|---|
| Wheel radius / width | 0.15 / 0.10 m | config.hpp / new |
| Rocker pivots | (0, ±0.40, 0.35) m | config.hpp |
| Wheel center from its pivot (front / rear) | (±0.45, 0, −0.20) m | config.hpp |
| Chassis box (L × W × H), center height | 0.80 × 0.50 × 0.20 m, z = 0.40 | new |
| Masses: chassis / each rocker / each wheel | 30 / 3 / 2.5 kg (46 kg total) | new |
| Rocker travel, joint damping | ±0.5 rad, 0.5 N·m·s/rad | new |
| Differential stiffness / damping | 5000 N·m/rad / 100 N·m·s/rad | new (static error ≈ 1e-4 rad) |
| Wheel torque / speed limit | 30 N·m / 10 rad/s (1.5 m/s) | new (turn-in-place needs ~19 N·m) |
| Tire friction μ longitudinal / lateral | 1.0 / 0.5 | new; lateral lower to emulate tire scrub |
| IMU rate, gyro σ, accel σ | 100 Hz, 0.002 rad/s, 0.02 m/s² | new |
| Rocker arm inset from wheel plane, thickness, height | 0.08 / 0.04 / 0.05 m | new (visual + collision only) |

Inertias come from the shapes: solid box (chassis), solid cylinder (wheels),
two thin rods (each rocker).

## Model structure

```
base_link (chassis box, IMU)
├── rocker_left_joint  (revolute, +y, at left pivot)
│   └── rocker_left (two arms)
│       ├── wheel_fl_joint (revolute, unlimited, +y) → wheel_fl
│       └── wheel_rl_joint → wheel_rl
└── rocker_right_joint (revolute, +y, at right pivot)
    └── rocker_right
        ├── wheel_fr_joint → wheel_fr
        └── wheel_rr_joint → wheel_rr
```

- Wheel links sit at the wheel centers; the tire cylinder is rolled 90° so its
  axis is the axle (+y). Tire friction: `fdir1 = 0 0 1` (the axle, in the
  collision frame), `mu` = lateral, `mu2` = longitudinal.
- Rocker arms run from the pivot to each wheel hub, inset toward the chassis,
  with box collisions (the rover can high-center on rocks). Self-collision
  stays off.
- Model plugins:
  - `RockerDifferential` (ours): see below.
  - `DiffDrive`: left joints `wheel_fl_joint`, `wheel_rl_joint`; right
    joints `wheel_fr_joint`, `wheel_rr_joint`; wheel separation = pivot
    spacing (0.80 m); subscribes `/model/rover/cmd_vel`, publishes
    `/model/rover/odometry` and `/model/rover/tf` (`odom` → `base_link`).
  - `JointStatePublisher` → `/model/rover/joint_states` (all six joints).
  - `OdometryPublisher` (ground truth, `world` → `base_link`) →
    `/model/rover/ground_truth`.
  - IMU sensor at the chassis center, frame id `base_link`, topic
    `/model/rover/imu` (needs the world's `Imu` system).

## Rocker differential plugin

`sim/plugins/rocker_differential.cpp`, a gz-sim `System` (Configure +
PreUpdate). Every step it applies the same torque to both rocker joints:

    τ = −k (q_L + q_R) − c (q̇_L + q̇_R)

This is a stiff spring-damper on the one motion a differential forbids (both
rockers turning the same way relative to the body) and leaves the allowed
motion (opposite rotation) free. Applying the same torque to both joints is
what a real differential does: it splits the reaction torque equally between
the sides. SDF parameters: `<left_joint>`, `<right_joint>`, `<stiffness>`,
`<damping>`. A missing joint is a configuration error (`gzerr`, plugin does
nothing).

It is a penalty method, so the constraint is slightly soft: under a chassis
moment M the error is M / (2k). Raise `stiffness` if that matters; the
explicit spring stays stable while √(k / I) · dt ≪ 2 (I ≈ 1.4 kg·m² per
rocker+wheels, dt = 1 ms → k up to ~10⁶).

Built by `sim/CMakeLists.txt` into `sim/build/`; Gazebo finds it through
`GZ_SIM_SYSTEM_PLUGIN_PATH`.

## World (`sim/worlds/rover_test.sdf`)

Ground plane (μ 1), sun, DART at 1 ms steps, systems Physics, UserCommands,
SceneBroadcaster, Imu. Static features ahead of the spawn point (rover at the
origin facing +x): a 10 cm step under the left wheel track only (x 2–3 m,
exercises the differential), a 15° ramp up to a 0.3 m platform and back down
(x 5–8.7 m), and a few rocks off to the sides. Includes the rover with
`model://rover`.

Pixi tasks: `sim-build` (CMake), `sim-model` (regenerate the SDF), `sim`
(depends on both; runs `run.sh`), `sim-bridge` (`parameter_bridge` with
`bridge.yaml`), `sim-test` (depends on both; runs all sim tests).
`run.sh` and the tests set `GZ_SIM_RESOURCE_PATH` / `GZ_SIM_SYSTEM_PLUGIN_PATH`
themselves.

## Tests

Generator unit tests: inertia formulas against hand-computed values; the SDF
passes `gz sdf -k`; joint tree, wheel positions, total mass and plugin
wiring match `Params`.

Headless physics tests (`gz.sim8.TestFixture`, DART, isolated
`GZ_PARTITION`), each on a world written by the test:

1. **Settles level:** after 2 s idle on flat ground, `base_link` within 2 cm
   of z = 0, roll and pitch below 1°, rockers within 0.01 rad of zero.
2. **Differential:** spawn with a 10 cm block under the front-left wheel only,
   settle 2 s. Geometry predicts `q_L ≈ −atan(0.10 / 0.90) / 2 = −0.0553`.
   Check `|q_L + q_R| < 0.005` rad, `q_L` within 0.01 rad of −0.0553, and all
   four wheel centers within 2 cm of one radius above the surface beneath them.
3. **Straight:** `vx = 0.5` m/s for 4 s → ground-truth x in [1.7, 2.1] m,
   |y| < 0.1 m, |yaw| < 0.05 rad.
4. **Turn in place:** `wz = 0.5` rad/s for 4 s → yaw in [1.2, 2.05] rad,
   translation < 0.15 m.
5. **Topics:** during 1 s, IMU (frame `base_link`, |accel| ≈ 9.8),
   joint states (six joints), wheel odometry and ground truth all publish.

Plus the demo world loads and the rover settles in it.

## Known limitations

- The differential is a penalty spring: slightly soft (error M / 2k).
- Skid-steer turning depends on the lateral/longitudinal μ ratio, a tuning
  knob, not a measured tire property. With the defaults the rover turns at
  ~87 % of the commanded rate; `DiffDrive` odometry assumes no slip, so it
  overestimates the turn — the real rover will need an effective track width.
- IMU sits at the chassis center but reports in `base_link`; orientation and
  angular rate are exact, linear acceleration differs by lever-arm terms.
- No TF for rockers/wheels in ROS (no `robot_state_publisher`).
- Python gz-sim system plugins cannot be used in models tested with the
  Python `TestFixture` (embedded interpreter conflict).
