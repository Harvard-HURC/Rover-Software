# URC 2027 mission scenarios in Gazebo — design

Date: 2026-10-06
Status: implemented 2026-10-06 (goal mode: the user asked for all URC
scenarios without pausing for questions; decisions below are ours and are
listed so they can be revisited). See "Changes during implementation".

## Goal

One Gazebo world per URC 2027 field mission, built to the published rules so
the team can rehearse each mission end to end in simulation:

| Mission (rule) | World | What it replicates |
|---|---|---|
| Autonomy (1.e) | `urc_autonomy.sdf` | Astronaut Assistance (go to astronaut, Follow!, Stay!, Fetch!, Come!, Give!) and Route-Finding (hill with one easy route, post behind the hill out of radio line of sight) |
| Equipment Servicing (1.d) | `urc_equipment_servicing.sdf` | ≤100 m drive to a mock lander with keyboard + ArUco tags, drawer, latched panel, two locks and a key, hose + cam-lock inlet, ¼-turn valve, buttons, switches, knobs; sample tube + cache container |
| Delivery (1.c) | `urc_delivery.sdf` | Staged course up to ~1 km: toolbox, pick-up/deliver objects, signs, search area, objects in a radio shadow, terrain from flat to boulder fields, steep slopes and drops |
| Astrobiology (1.b) | `urc_astrobiology.sdf` | Site within 0.5 km of C2 with distinct geologic units (banded Morrison-like hills, dry wash, gypsum, biological soil crust, shrubs) |

The SAR (3.a.iii) is a document, not a field mission, so it has no world.

Source: *University Rover Challenge 2027 – Requirements and Guidelines* and the
URC Q&A as of 2026-10-03 (urc.marssociety.org). Every number taken from the
rules lives in `sim/urc/rules.py` with its rule reference.

## Decisions

| Topic | Decision | Why |
|---|---|---|
| Generation | Python generator `sim/gen_worlds.py` + package `sim/urc/`, deterministic (seeded), writes worlds, models, textures, heightmaps and mission sheets | Same approach as `gen_model.py`: numbers in one place, regenerated by a pixi task |
| Terrain | Procedural heightfields (numpy), 16-bit PNG Gazebo heightmaps; collision + textured visual | Prototyped: DART (ODE detector) heightmap collision works, 15° climb matches, a 1 km map costs the same as 64 m (~2.9× real time) |
| Real DEM | Not used; the terrain is synthetic but placed at the real coordinates | The official URC DEM is not released yet (Q&A Autonomy 20); downloading USGS data needs the user's go-ahead. Each world exports its heightfield as a GeoTIFF so teams can practice with DEM tooling now |
| Rocks | Generated rock meshes (OBJ with normals), mesh collision | Prototyped: same speed as primitive rocks |
| Textures | Procedural PNGs (terrain layers + normal maps, ArUco tags from OpenCV, sign text with DejaVu) | No downloads; ArUco tags verified by OpenCV detection in sim camera images |
| Coordinates | Each world sets `<spherical_coordinates>` (WGS84, ENU) at the real site; x east, y north | NavSat then reports real lat/lon; mission sheets give WGS84 coordinates like the judges do (rule 3.d.v) |
| Rover sensors | Add GNSS (navsat), front RGB-D camera, and a rear status LED to `gen_model.py` | Needed by every mission (GNSS "essential", AR tags, LED rule 1.e.ii). The arm is out of scope (no design yet) |
| Rendering | Worlds load the Sensors system (ogre2); `run.sh` and tests set `OGRE2_RESOURCE_PATH` | The conda gz-rendering build has a space-padded OGRE plugin path; the env var fixes it (prototyped) |
| Astronaut | Articulated primitive figure (arms can beckon); moved by the referee with `set_pose` | No actor meshes in the env; scripted motion is repeatable |
| Interactive parts | Real joints (prismatic keys/buttons/drawer, revolute hinge/latch/valve/switches/knobs/locks/lids), state via `JointStatePublisher` | An arm can operate them later; the referee judges from joint states and poses |
| Judging | `sim/referee.py` — runs alongside a world, scripts the astronaut, judges tasks, reports radio line of sight | Turns static worlds into missions; pure-Python core so it is unit-testable |

## Package layout

```
sim/
  gen_worlds.py           CLI: pixi run sim-worlds
  referee.py              CLI: pixi run referee <mission>
  urc/
    rules.py              URC 2027 numbers (rule refs)
    geo.py                local ENU <-> WGS84 (same math as Gazebo)
    sdf.py                XML helpers
    terrain.py            Heightfield: synthesis ops, sampling, slope, line of sight, PNG/GeoTIFF export
    textures.py           terrain layers, normal maps, ArUco tags, signs
    meshes.py             rock meshes, textured quads, terrain-draped decals (OBJ)
    props.py              AR post, astronaut, rock pick hammer, C2 station, landing pad, start gate,
                          rocks, delivery objects, signs, cache container, sample tube, fuel tank + hose, shrubs
    lander.py             equipment-servicing lander
    world.py              world assembly (physics, systems, sky, sun, terrain, includes) + mission sheet
    missions/             autonomy.py, equipment.py, delivery.py, astrobiology.py: layouts
    judge.py              referee core (no gz imports): mission state machines
  models/urc_*            generated model directories
  worlds/urc_*.sdf        generated worlds
  worlds/urc_*.json       generated mission sheets
  worlds/urc_*/           generated per-world terrain assets (heightmap, GeoTIFF, decals)
```

## Mission sheet

`worlds/urc_<mission>.json` is what judges would hand out plus what the
referee needs: world name, spherical origin, C2 antenna, start pose, terrain
metadata (heightmap path, size, z range — enough to sample heights), and per
task: id, rule ref, description, WGS84 + local coordinates, tolerances, and
ground-truth objects. Generated from the same layout code as the world, so
they cannot disagree.

## Worlds

All worlds: DART at 1 ms, real-time factor 1; systems Physics, UserCommands,
SceneBroadcaster, Imu, NavSat, Sensors (ogre2); sun with shadows, sky; terrain
heightmap (collision μ 0.8 + height-blended textures) over a flat horizon
plane; C2 station (trailer + 3 m antenna mast, rule 2.c.iv); start gate; the
rover. Coordinates below are local ENU metres.

### Autonomy (`urc_autonomy`)

Origin 38.4180 N, −110.7770 E: the middle of the state-owned square mile
(rule 1.e.xiii, 38.411–38.425 N, −110.786 to −110.768 E). Terrain 640 m,
0.625 m resolution. Rover starts at C2.

- **Astronaut Assistance** (east, gently rolling): astronaut waits at the
  provided GNSS location; Follow! walk ~45 m to a destination; rock pick hammer
  on the ground there; Stay! the astronaut walks >20 m away; Come! from ≥20 m;
  Give! hammer on the ground. Tolerances 3 m (1.e.v, vi, ix).
- **Route-Finding** (north): start post (ArUco 0) on flat ground; a hill with
  cliffs on most sides, one easy ramp (~12°) and one steep gully (~25°), Post 1
  (ArUco 1) on top; Post 2 (ArUco 2) behind the hill, out of line of sight of
  the C2 antenna (1.e.xv, xvi). Tolerance 1 m + LED arrival signal (1.e.xvii).
- Drone landing pad near the start (1.e.xiv). Scattered rocks and a rubble
  field for obstacle avoidance.

AR posts (1.e.xii): three 20×20 cm faces around a pole, centre 1.0 m above
ground (allowed 0.5–1.5 m), 4x4_50 tag with a one-cell white border (2.5 cm
cells), same tag on all three sides. Tag IDs 0/1/2 decoded from the rules'
figure.

### Equipment Servicing (`urc_equipment_servicing`)

Origin near MDRS (38.4064 N, −110.7919 E). Terrain 256 m, 0.25 m resolution,
nearly flat with pebbles. Start gate at 90 m from the lander (≤100 m, 1.d.i).
A sample stand near the start holds the sample tube and cache container
(handle ≥10 cm long, ≤5 cm diameter, <5 kg; hinged lid and lock knob).

Lander: a 2.4 m wide mock-up on a world-fixed base; everything to service is
between ground and 1.5 m:

- Keyboard (Redragon K552, 87 keys, vertical) with 2×2 cm ArUco tags 1–4 at
  the corners (1 TL, 4 TR, 2 BL, 3 BR as in the rules' figure) and a 4.3"
  e-paper display above it. Keys are spring-return prismatic joints; the
  referee decodes key presses into typed text and judges the launch key.
- Drawer (prismatic) with a tight-fitting slot for the cache.
- Hinged panel (revolute) held shut by a latch lever (revolute).
- Lock A holding a tubular key (1×1 cm tags 5/6 on the key, tags 1–4 around the
  keyholes); lock B empty; both cylinders revolute.
- Fuel tank on the ground with a segmented hose (ball joints) ending in a
  1.5" cam-lock coupler; matching inlet on the lander (push-on).
- ¼-turn lever valve, 3 push buttons, 3 toggle switches, 2 knobs.

### Delivery (`urc_delivery`)

Origin near MDRS. Terrain 1024 m, 1 m resolution; C2 in the south-west,
difficulty rising with distance (1.c.ii): flat start, rough gravel, a dry wash,
a boulder field, 20–30° loose slopes, 0.3–1.0 m ledges, a ridge that puts the
later tasks out of radio line of sight. Objects ≤5 kg, <40 cm cube, graspable
feature ≤7.5 cm (1.c.iii).

- Stage 1 (line of sight): open a toolbox (hinged lid) and deliver the wrench
  to astronaut A; astronaut B holds a sign naming the object to bring; deliver
  a supply crate up a slope.
- Stage 2 (rugged, partly out of sight): a field sign; find an instrument case
  in a 40 m search area; deliver a first-aid kit across the boulder field to
  astronaut C behind the ridge; find a dropped tool in the wash (radio shadow).

### Astrobiology (`urc_astrobiology`)

Origin near MDRS. Terrain 1024 m, C2 at the centre, site boundary within
0.5 km (1.b.ii). Units: banded mudstone hills (height-banded colours), a dry
sandy wash, a gypsum outcrop, biological soil crust patches, a sandstone ledge,
sparse shrubs. Each unit is a terrain-draped decal and a ground-truth entry in
the sheet. Individual sample sites are unmarked (Q&A Astrobiology 5).

## Rover additions (`gen_model.py`)

| Sensor | Topic (gz) | ROS 2 (bridge) |
|---|---|---|
| GNSS (navsat, 10 Hz, σ 0.5 m horizontal / 1.0 m vertical) | `/model/rover/navsat` | `/gps/fix` |
| RGB-D camera, front, 640×480, 15 Hz, 1.5 rad HFOV | `/model/rover/camera/{image,depth_image,points,camera_info}` | `/camera/...` |
| Status LED (rear, rule 1.e.ii) | `/model/rover/led` (StringMsg: `red`, `blue`, `green`, `off`) | `/led` |

The referee recolours the LED visual (`/world/<w>/material_color`; `green`
flashes) and uses the LED state for arrival judging.

## Referee

`pixi run referee <mission>` (runs next to `pixi run sim <world>`):

- Reads the mission sheet; subscribes to the rover ground truth, the LED, the
  lander joint states and dynamic poses.
- Core (`urc/judge.py`, no Gazebo imports): one state machine per mission,
  `step(t, observation) -> actions`, so it is unit-tested with synthetic data.
- Actions: move the astronaut (`set_pose_vector`, following the terrain), arm
  gestures (joint position commands), astronaut commands on
  `/astronaut/command` (device), `/astronaut/speech` (word, stands in for
  audio), recolour the LED.
- Publishes `/urc/score` (JSON) and prints events. Reports radio line of
  sight between the C2 antenna (3 m) and the rover on `/urc/radio`.
- Judging rules: distances from the rover footprint; "stopped" = speed
  < 0.05 m/s for 2 s; route targets need the LED `green` while stopped within
  1 m; delivery = object at rest within 2 m of the location; Equipment
  Servicing tasks from joint angles and part poses.

## Tests

- Unit (no physics): geo round-trip; rules constants; ArUco textures decode to
  their IDs; AR post geometry; terrain ops (heights, slopes, line of sight);
  every mission layout satisfies its rules (distances, bounds, NLOS of Post 2,
  easy-route max slope, cliff slopes); judge state machines on synthetic
  streams; all generated SDF passes `gz sdf -k`.
- Headless (TestFixture): each world loads and the rover settles on the
  terrain at its spawn; NavSat matches the sheet's start coordinates; the
  rover camera at the route start sees ArUco 0 (rendered, OpenCV); a lander
  key pressed by a test force is detected.

## Out of scope

The robotic arm and its grasping; science instruments and digging (the
Astrobiology world provides sites, not soil physics); the drone; RF
propagation beyond geometric line of sight; deformable/loose soil.

## Known limitations

- Terrain is synthetic. Replace with the official DEM when URC releases it.
- Heightfields cannot have vertical faces; vertical drops are rock/box models.
- One friction value for the whole terrain (no sand/gravel difference).
- The astronaut is teleported along its path (no walking animation physics).

## Changes during implementation

- **World origin.** Layouts are written relative to the C2 station, but each
  world's origin is the terrain's centre and lowest point: DART ignores the
  heightmap `<pos>` and ogre2 ignores the model pose, so that is the only
  placement where the visual and collision terrain agree. Sheets report world
  coordinates; `run.sh` points the GUI camera at the rover.
- **Rocks and decals are shapes of the terrain link**, not separate static
  models (3x faster: separate bodies were all broadphase-paired with the
  heightmap).
- **At most four terrain textures** (ogre2 limit); Astrobiology bands use four.
- **`JointMonitor`** (C++ system, `sim/plugins/`) replaced `JointStatePublisher`
  for the lander (which publishes every step here) and also reports link world
  poses, so every tracked prop uses it: the referee reads `/model/<name>/state`.
- **GNSS noise** is configured in metres and converted to degrees (Gazebo
  applies it to latitude/longitude).
- **Tests** strip the Sensors system from world copies and render the camera
  test in a subprocess (ogre2 starts once per process, on the main thread).
