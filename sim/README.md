# Rover simulation (Gazebo Harmonic)

A generic model of our rover: rectangular chassis, rocker suspension with a
differential (4 wheels, a rocker-bogie without the bogies), tank / skid-steer
drive, an RGB-D camera on a pan-tilt head. Geometry is the placeholder from
`driver/include/rover_driver/config.hpp` until the mechanical numbers arrive.
Around it: the URC 2027 mission worlds, a proving ground, a referee and a
browser driver station.

Design specs in `docs/superpowers/specs/`: `2026-10-05-gazebo-rover-model-design.md`
(the rover), `2026-10-06-urc-scenarios-design.md` (the URC worlds). The realism
work in `2026-10-06-urc-realism-design.md` (per-contact terrain friction, a
physical drivetrain, lidar terrain, new rendering, Fly and Map views) is not
implemented yet; nothing below describes it.

## Quick start

```bash
pixi run sim                    # build the plugins, regenerate rover and worlds, open Gazebo (rover_test)
pixi run drive urc_autonomy     # or drive from the browser: starts the world headless, opens the station page
pixi run sim-bridge             # second terminal: ROS 2 <-> Gazebo topics
pixi run ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.3}, angular: {z: 0.2}}'
pixi run sim-test               # headless tests
```

`pixi run sim <world>` opens another world: a path to an `.sdf` or a name in
`sim/worlds` (`rover_test`, `urc_autonomy`, `urc_equipment_servicing`,
`urc_delivery`, `urc_astrobiology`, `proving_ground`). The GUI camera starts on
the rover; with `--follow` it follows it, 5 m behind and 2.5 m up
(CameraTracking `/gui/follow`, then `/gui/follow/offset`). In the GUI you can
also drive with the Teleop plugin (⋮ menu → Teleop, topic `/model/rover/cmd_vel`).

On macOS Gazebo cannot run its server and GUI in one process, so `sim/run.sh`
starts the server in the background and the GUI in the foreground; closing
the GUI stops both.

Joint names: `rocker_left_joint`, `rocker_right_joint`, `wheel_{fl,rl,fr,rr}_joint`,
`camera_pan_joint`, `camera_tilt_joint`. Rocker angle is positive when the
rocker's front goes down (rotation about +y); wheel angle is positive rolling
forward. The head's angles are from straight ahead and level: pan positive to
the left (±2.8 rad), tilt positive down (−0.6 rad up to +1.2 rad down, starting
at 0.12). `JointPositionController`s in velocity mode slew the head at 2 rad/s
to the angle last sent. `base_link` is the driver's body frame: x forward, y
left, z up, on the ground midway between the wheels.

## Changing the rover

Edit `Params` in `gen_model.py`, then `pixi run sim-model` (`sim`, `drive` and
`sim-test` do it for you). Masses, inertias, wheel positions, the
differential, motor limits, tire friction, the sensors and the camera head all
come from there; `ChaseParams` and `EyeParams` set the station's cameras.

## Driver station

```bash
pixi run drive urc_autonomy          # starts the world headless if nothing runs, opens the page
pixi run sim urc_autonomy --follow   # or: the Gazebo GUI, its camera following the rover...
pixi run drive                       # ...and the station attached to it (second terminal)
```

`pixi run drive [world] [--no-browser] [--port N] [--host H] [--world-name NAME] [--released]`:
- `world`: a path to an `.sdf` or a name in `sim/worlds`. With a world and
  nothing running, the station starts `gz sim -s -r <world>` with `run.sh`'s
  environment, stops it on exit and exits when it exits. A world that fails
  to load ends the wait at once ("gz sim exited (code N) before <world> came up").
- Without `world` it attaches to the running simulation (it finds
  `/world/<name>/clock` on the transport); `--world-name` picks one.
- It spawns its two cameras (`model://eye_camera`, `model://chase_camera`, via
  `/world/<w>/create`) unless they are already in the world.
- `--port`: default 8765; without it, a port in use moves it to the next, up to 8774. The URL is printed.
- `--released`: start handed over to the autonomy stack.

One page, one keyboard focus: driving and the cameras use the same keys.
Click the page to drive; the rover holds still while the page lacks focus.

| Keys | Action |
|---|---|
| W / S | forward / back (hold) |
| A / D | turn left / right (hold) |
| Shift | twice the preset (capped at 1.5 m/s, 1.5 rad/s) |
| 1 / 2 / 3 | speed preset 0.25 / 0.6 / 1.2 m/s (0.4 / 0.8 / 1.2 rad/s) |
| Space | stop now |
| ← → ↑ ↓ | eye and onboard views: look left, right, up, down (1 rad/s); chase view: orbit, raise, lower |
| mouse drag on the video | eye and onboard views: look around (the point under the pointer stays under it); chase view: orbit |
| C or double-click | centre the look (ahead, 0.12 rad down); in the chase view a double-click puts the camera back behind the rover |
| J L / I K | look left, right / up, down in any view |
| + − or mouse wheel | zoom the chase camera (also while it is the small view) |
| F / R | chase camera: follow the heading or hold a world direction / back behind the rover |
| V / P / M / H | next main view / show or hide the small view / map zoom / help |
| Gamepad | left stick drive; right stick looks or orbits in the big view; D-pad looks in any view; LB/RB zoom; RT fast; B stop; X next view; Y follow or hold |

Views (V cycles them): **Rover eye** (the default), **Chase camera**, **Onboard
camera** and **Onboard depth** (the RGB-D sensor's pictures). The small view
shows the chase camera, or the eye while the chase camera is big; click it to
swap. Both show the whole picture, letterboxed.

The page shows the main and the small view; where the eye looks ("Rover eye,
32° left, 12° down"; the onboard views show the measured head angles); speed
and turn rate, measured against what you command; heading, pitch, roll and
height; a side view of the rover with both rocker angles, the differential
error (left + right, which the differential keeps at 0) and 30 s of rocker
history; the four wheels' ground speeds and the head angles; GNSS position;
sim time and real-time factor; the LED; the referee's score and radio line of
sight while `pixi run referee` runs; and a map: a hillshade of the mission
sheet's heightmap with its places, the rover and its track (click or M zooms to
250 / 60 m around the rover). Worlds without a sheet get a grid.

How it works:
- `server.py` (aiohttp) and `link.py` (gz-transport). The page sends the held
  keys and stick axes over a WebSocket at 20 Hz, camera moves as small deltas;
  telemetry comes back at 10 Hz.
- `drive.py` turns inputs into a twist under acceleration limits: 1.0 m/s² and
  2.0 rad/s² speeding up, 2.0 m/s² and 4.0 rad/s² slowing down.
- While the station has control it publishes `/model/rover/cmd_vel` at 20 Hz
  and `blue` on `/model/rover/led` at 2 Hz (rule 1.e.ii: teleoperation).
- Deadman: if the page stops sending for 0.5 s (tab closed, focus lost,
  network gone) the twist is zero. Pressing Cmd lets go of all held keys
  (macOS browsers send no keyup for keys released while Cmd is down).
- "Release to autonomy" sends one zero twist, then stops the station's
  cmd_vel, LED and head messages so the team's stack can drive; "Take control"
  takes them back, at the same speed preset.
- Cameras are MJPEG streams (`/stream/<eye|chase|rgb|depth>`; one JPEG at
  `/frame/<camera>`). A camera is subscribed, and so rendered, only while
  someone watches it; a hidden tab drops its streams. The first picture after
  subscribing is dropped (see Gazebo lessons). Depth is coloured on a log
  scale from 0.1 to 40 m; black means no return.
- Page messages with non-finite numbers (NaN, Infinity, 1e309) get an error
  reply; the ChaseCamera plugin also drops non-finite commands.

Stopping and sharing:
- Ctrl-C, kill (SIGTERM) and closing the terminal (SIGHUP) stop the station the
  same way at any time: the rover gets a zero twist if the station was
  serving, and a world the station started gets SIGINT, then SIGKILL after
  10 s or at once on a second Ctrl-C. That world runs in its own session, so
  the terminal never reaches it. A signal ignored from the start (nohup) stays
  ignored. A SIGKILLed station leaves the rover's last cmd_vel in force.
- One world per `GZ_PARTITION`, one station per world: the rover's topics are
  not world-scoped. Run separate worlds with `GZ_PARTITION=<name>`; the
  station warns when several share its partition.
- Stations announce themselves on `/driver_station/announce` (StringMsg, JSON
  `id`, `world`, `url`) at 2 Hz. A second station in the partition exits
  ("another driver station is attached to <world> (<url>)"); if two start
  within about a second, both pages say "Another driver station is attached".
  A station in control overrides autonomy's cmd_vel by design.
- When `/world/<w>/stats` stops for 3 s, telemetry blanks and the page says
  "Simulation not running: waiting for it"; when the world returns the station
  spawns its cameras again.
- A camera counts as present only while its plugin's state topic delivers
  (5 Hz). The console says per camera "spawned", "already in the world", "not
  spawned, the world has no /world/<w>/create (UserCommands system)", or that
  its plugin does not report (`sim/build` missing from `GZ_SIM_SYSTEM_PLUGIN_PATH`).

**Rover eye** (`models/eye_camera`, `EyeParams`): 960×540 at 20 Hz with the
RGB-D sensor's 1.5 rad horizontal field of view. Near clip 0.1 m (it also
hides the camera's own housing, all within 0.1 m of the pivot), far clip
2000 m, so it sees the horizon (the sensor stops at 40 m). The `ChaseCamera`
plugin in eye mode (`<mount>` in the SDF) places it every step at rover pose ×
`Params.camera_xyz` × Rz(yaw)·Ry(pitch): body-fixed, it pitches and rolls with
the chassis like the real camera; unsmoothed, one 1 ms step behind the rover
(measured at most 0.9 mm off the pivot while driving over a 6 cm plank and
turning; the test allows 1 cm). Looking only turns it, within the head's
limits. The look lives in the station (`drive.Look`, so a page reload keeps
it); every change goes to the eye at once (`/eye_camera/look`) and, while the
station has control, to the head, so the onboard camera sees what you see.
Released, the eye still turns but the head belongs to the autonomy stack. The
look is re-sent every second for cameras spawned later.

**Chase camera** (`models/chase_camera`, `ChaseParams`): gravity off, no
collisions, an RGB camera (960×540, 20 Hz, 1.2 rad). Every step the plugin
puts it on a sphere around a point 0.5 m above the rover, looking at it.
Follow mode: yaw relative to the rover's heading (0 = behind); orbit mode: yaw
is a world direction. A 0.25 s first-order lag smooths it, so it trails a
turning rover by turn rate × 0.25 s. Pitch is clamped to 0.05–1.45 rad (never
below the rover), distance to 1.5–80 m. It does not avoid terrain: on steep
downhills raise it with ↑.

| Gazebo topic | Type | |
|---|---|---|
| `/eye_camera/image` | Image | 960×540, 20 Hz |
| `/eye_camera/look` → | Vector3d | x: yaw = pan [rad] (left +), y: pitch = tilt [rad] (down +), absolute; clamped to the head's limits |
| `/eye_camera/state` | StringMsg | JSON at 5 Hz: mode `eye`, target, yaw, pitch |
| `/chase_camera/image` | Image | 960×540, 20 Hz |
| `/chase_camera/cmd` → | Vector3d | x: +yaw [rad], y: +pitch [rad], z: zoom (distance × eᶻ) |
| `/chase_camera/mode` → | StringMsg | `follow`, `orbit`, `reset` |
| `/chase_camera/state` | StringMsg | JSON at 5 Hz: mode, target, yaw, pitch, distance |
| `/driver_station/announce` | StringMsg | JSON at 2 Hz: id, world, url |

## Design notes

### Why the differential is a plugin, not a mimic joint

The obvious way to model a differential in SDF is a mimic joint:
`rocker_right_joint` mimics `rocker_left_joint` with multiplier −1. We tried
it first (2026-10-05) and measured, in this env (gz-sim 8.10, gz-physics 7,
DART 6.19):

- **Only the Bullet-Featherstone engine implements mimic** in Gazebo
  Harmonic; DART ignores the tag.
- **Under Bullet the mimic differential is excellent.** With a 10 cm block
  under the front-left wheel the rockers settled at −0.0558 / +0.0558 rad
  (geometry: ±0.0553), and the coupling is two-sided — pushing either rocker
  moves both equally, like a real differential.
- **But under Bullet the rover cannot turn in place.** Commanding 0.5 rad/s
  for 4 s gave zero yaw while the wheels spun at full speed. Bullet's
  friction is a box model: a wheel sliding forward keeps its full sideways
  grip, and because the half-wheelbase (0.45 m) is longer than the half-track
  (0.40 m), sideways scrub always beats the drive. The usual fix, lower
  sideways friction on the tires (`fdir1` + `mu`/`mu2`), is ignored by
  Bullet. So is joint damping; and Bullet applies SDF's default torsional
  friction (1.0) as spinning friction that also blocks yaw.
- **DART honors the anisotropic tire friction**: lateral μ 0.5, longitudinal
  μ 1.0 turned the rover 1.74 of a commanded 2.0 rad in 4 s.

So the world runs DART, and `plugins/rocker_differential.cpp` provides the
differential. Every step it applies the same torque to both rocker joints:

    τ = −k (q_L + q_R) − c (q̇_L + q̇_R)        k = 5000 N·m/rad, c = 100 N·m·s/rad

That is a stiff spring-damper on the motion a differential forbids (both
rockers turning the same way relative to the body), leaving the allowed motion
(opposite rotation) free. Equal torque on both joints is exactly what a real
differential does — it splits the reaction torque between the sides. It is
slightly soft: a moment M through the differential leaves an error of
M / 2k (~1e-4 rad here). If a later Gazebo implements mimic in DART, the
plugin can be replaced by the `<mimic>` tag.

The plugins are C++ rather than Python gz-sim systems because Python systems
crash Gazebo's in-process Python test fixture.

### Skid-steer friction

Tires use `mu2 = 1.0` along the direction of travel and `mu = 0.5` along the
axle (`fdir1`). The ratio is a tuning knob, not a measured tire property:
lower lateral μ turns faster. With the defaults the rover turns at ~87 % of
the commanded rate on bare ground (measured again 2026-10-06: 1.739 of 2.0 rad
in 4 s). `DiffDrive` odometry assumes no slip, so `/odom` overestimates turns;
compare with `/ground_truth/odom`. The real rover will need an effective track
width for the same reason.

DART combines the tire's μ with the ground's as min(μ_a, μ_b) in each
direction. On ground of μ ≤ 0.5 both directions get the same μ, the box
friction is isotropic again, and the rover cannot turn in place (measured
2026-10-06, 0.5 rad/s for 4 s on boxes: μ 0.4 and 0.5 gave 0.000 rad and a
0.6–0.7 m slide; μ 0.6 gave 0.75 of the command; μ 1.0 0.87). That affects the
sand, scree and clay zones and the proving ground's μ 0.20 / 0.35 / 0.50 lanes.

## Known limitations

- The differential is a penalty spring (slightly soft, see above).
- Traction is μ only: no sinkage, rolling resistance or bulldozing, and no
  turning in place on ground of μ ≤ 0.5 (see skid-steer friction).
- DiffDrive has no command timeout: if whatever publishes `cmd_vel` dies
  (a SIGKILLed station, a crashed autonomy node), the rover keeps driving with
  the last twist. The station sends a zero twist whenever it stops normally.
- The IMU sits at the chassis center but reports in `base_link`: orientation
  and angular rate are exact, linear acceleration differs by lever-arm terms.
- No TF for rockers and wheels in ROS (no URDF / `robot_state_publisher`).
- Sensors are GNSS, one RGB-D camera on a pan-tilt head and the IMU; no lidar.
  Cameras render only in worlds with the Sensors system (every generated world
  and `rover_test`).
- The RGB camera (640×480 over 1.5 rad, f = 343 px) reads a 20 cm ArUco face
  (2.5 cm cells) reliably only within about 2.5 m, square on: at 3 m 2 of 4
  post yaws failed, and faces 30–60° off decode only by luck from 3 m
  (measured, OpenCV's default detector). A team's HD camera reads further.
- Altitudes: the Autonomy world gives WGS84 ellipsoidal heights (what NavSat
  and a real receiver report). The other worlds' origins carry NAVD88
  elevations from USGS point values (the proving ground borrows Equipment
  Servicing's), about 20.9 m above the ellipsoidal heights a receiver would
  report there. Heights within a world are right.
- One world per `GZ_PARTITION`: the rover's topics are not world-scoped.
- The chase camera does not avoid terrain.
- Gazebo prints `XML Element[gz_frame_id], child of element[sensor], not
  defined in SDF` on load. Harmless: `gz_frame_id` is a gz-sensors extension
  that sets a sensor's frame id; SDF has no standard element for it.

### Autonomy: the real square mile

**Terrain source.** USGS 3D Elevation Program 1 m DEM, public domain, fetched
2026-10-06 from the 3DEPElevation ImageServer `exportImage` service: bbox
−110.790, 38.407, −110.764, 38.429 (W, S, E, N), EPSG:4326, 2268 × 2442 px,
float32, bilinear. The request URL is in `data/dem/route_area_3dep.json`, which
the sheet quotes under `judges_only.terrain_source`.
- `data/dem/route_area_3dep.tif`: 8.8 MB, deflate + floating-point predictor
  (lossless, bit-identical to the download), all GeoTIFF tags kept. It covers
  lat 38.40400–38.43200, lon −110.790…−110.764, which contains the square mile
  (`rules.ROUTE_AREA`). Elevations 1341.6–1430.8 m NAVD88, no gaps. The service

### Ground types and friction zones

`urc/terrains.py` is the one catalogue of ground (`TYPES`). Worlds pick by
name and never repeat a μ or a colour:

| Type | Title | μ | Holds or climbs up to atan(μ) | Used as |
|---|---|---|---|---|
| `gravel` | Gravel | 0.60 | 31° | friction zone |
| `sand` | Soft sand | 0.40 | 22° | friction zone |
| `scree` | Loose scree | 0.35 | 19° | friction zone (steep loose slopes, 1.c.ii) |
| `clay` | Dusty bentonite clay | 0.25 | 14° | friction zone |
| `slickrock` | Slickrock sandstone slab | 1.0 | | decal (the heightmap grips at 1.0 too) |
| `biocrust`, `gypsum` | Biological soil crust, Gypsum crust | 1.0 | | decals |
| `regolith`, `pavement`, `mudstone`, `bentonite`, `caprock` | Packed regolith (the default ground), Desert pavement, Maroon mudstone, Grey bentonitic mudstone, Sandstone caprock | 1.0 | | terrain layers |
| `calibration_surface(mu)` | Test surface μ x | any | | proving-ground lanes, pale blue-grey (slippery) to dark (grippy) |

`ROCKS` holds the rock palettes (`desert`, `lichen`), `SHRUBS` the shrub
colours. μ is a tuning knob, not a measured property: DART has no sinkage or
rolling resistance, so friction is the only lever. The tires have μ 1.0 along
the tread and 0.5 across it: a zone μ above 1.0 changes nothing, one above 0.5
only the grip along the tread, and at 0.5 or below the rover cannot turn in
place (skid-steer friction, above). Each type's texture and normal map are
made once into `urc_media/textures/ground_<type>_<hash>.png` and shared by
every world.

**Why zones need tiles.** Gazebo honours `<friction><ode><mu>` only on
primitive collision shapes; heightmaps and meshes always have μ 1.0
(`HEIGHTMAP_MU`), and DART combines two touching shapes as min(μ_a, μ_b). A
wheel that touches the heightmap anywhere is held at μ 1. So a zone below μ 1
must be the only thing its wheels touch:
- **Tiles**: 0.1 m thick boxes with the zone's μ on a 1.5 m grid, collision
  shapes of the terrain's own link. Each is tilted to the least-squares plane
  of the ground under it and lifted `TILE_CLEARANCE` (1.5 cm) above its
  highest point. Neighbouring cells merge into rectangles up to 24 m wherever
  the ground is planar within `FLATNESS` (2 cm). Round zones tile every cell
  whose centre lies inside the outline (tiles reach up to 1.06 m past it);
  rectangular zones put tile edges on the profile's kinks.
- **Flat ground**: `terrains.fit_tiles` refuses (ValueError) ground that is
  not planar within 2 cm under one 1.5 m tile, so every tile is 1.5–3.5 cm
  above the terrain and neighbours leave no kerb. `features.Patch` levels the
  ground to its plane out to `TILE_REACH` (1.08 m) past the outline; a `Wash`
  with a channel keeps its sand on the floor (`sand_radius + TILE_REACH ≤
  half_width`, defaults 6.5 and 8 m, else ValueError); `Heightfield.strip`
  keeps lanes planar to their edges.
- **Decal**: a textured mesh 2 cm above the surface, covering the outline plus
  0.2 m. A zone of μ 1.0 is only its decal.
- **Rocks off the tiles**: a rock mesh has μ 1 and would be a foothold, so
  `rock_field` drops colliding rocks over tiles, and declaring a zone over
  earlier colliding rocks or under a placed model raises ValueError. Declare
  zones (`features.dress`) before rocks and objects; `place()` and `rover()`
  stand objects on the tile tops.
- Measured on the proving ground, rover parked 3 s on the 20° ramp: the μ 0.20
  lane slides 5.37 m; the same lane without its tiles holds (−0.015 m); μ 0.95
  holds (−0.013 m). No carved collision heightmap is needed.

### Building blocks

Every world is built from shared, parameterised parts. A world module only
says where and how much; it has no scattering, tiling or terrain-shaping loops
of its own.

- **Terrain features** (`urc/features.py`): frozen dataclasses.
  `features.shape(hf, FEATURES)` edits the heightfield in `make_terrain()`;
  `features.dress(w, FEATURES)` adds zones and blocks right after
  `w.terrain()`. Dressing in list order keeps a world's zones the same.
  - `Patch` (a levelled natural zone; `level=False` for a decal-only crust) and `along` (patches along a path).
  - `Wash`: a channel `depth` deep (0 on a real DEM) with `<key>_sand_<k>` patches.
  - `Mesa`; `Slope` (a planar chute with its zone, e.g. scree).
  - `Lane` + `Surface`: a graded strip (profile [(length, grade)], optional side tilt) with zones side by side; `Lane.describe()`.
  - `Washboard`, `AlternatingBumps`, `TwistDitch`, `Step`.
  - `Ledge`: a vertical drop with a lip. Level ground behind the shelf for its
    depth + 3 m, then the drop, then 4 m of level ground below, blending back
    over 4 m; boxes in the terrain link cover the heightfield's slope down the
    step. Rocks keep clear of its edge.
- **Heightfields** (`urc/terrain.py`): `Heightfield` ops `noise`, `flatten`,
  `mesa`, `ramp`, `channel`, `ridge`, `level`, and the windowed `strip`, `bump`,
  `washboard`; queries `height`, `slope_deg`, `line_of_sight`,
  `max_grade_along`; helpers `terrain.resample`, `terrain.path_distance`,
  `terrain.kinks`.
- **`WorldBuilder`** (`urc/world.py`), in layout coordinates:
  - `terrain([Layer(name, start, fade)])`: at most 4 catalogue layers (ogre2's limit).
  - Zones: `zone`, `zone_rect` (μ always the type's).
  - Rock placements: `scatter(count, center, radius, sizes, avoid, clearance, min_slope)`,
    `scatter_each(spots, count, ...)` (one disc per (x, y, radius)),
    `keep_clear(paths, step)` (placed models plus points along routes, to pass as `avoid`).
  - Rock groups: `rock_field(name, rocks, colliding_size, palette)`;
    `rock_garden(name, x, y, length, width, size, yaw, ...)` (every rock
    collides, cell `garden_spacing(size)` = 0.7 + 3 × size). Each rock's flat
    base is tilted to the slope and sunk 8 % of its size.
  - Shrubs: `shrubs(points)` with `scatter_points` / `points_along`; visual only.
  - At `write()` rocks and shrubs are merged into one mesh per 128 m chunk
    (and colour, for visuals) in the terrain link: visuals
    `rocks_<i>_<j>_c<k>`, `shrubs_<i>_<j>_c<k>`, collisions `rocks_<i>_<j>`.
  - Other parts: `ring` (boundary stakes), `block`, `station` (a field sign
    plus a sheet point), `c2`, `rover`, `place`, `include`, `mark`, `point`,
    `task`, `radio_los`, `to_world` / `to_layout`, `height`, `ground`.
- **Shared assets** (`urc/media.py`, `Media`): textures and meshes in
  `models/urc_media`, each named `<stem>_<hash>.png|obj`. The hash covers the
  generator function, its arguments and its module's source, so a file is made
  once and skipped while current, also on later runs (`media.texture(stem,
  make, *args)`, `media.mesh(...)`, `aruco`, `sign`, `quad`). A world's own
  model (`urc_terrain_<key>`) holds only its heightmap, `dem.tif`, zone decal
  meshes and merged rock and shrub chunks.
- **Reading a world back** (`urc/sheet.py`), the one reader for the referee,
  judges, station map and tests: `path(world)`, `find(world, world_path)`,
  `load(path)`, `terrain(sheet, path)` (a Heightfield in world coordinates),
  `radio_los(hf, antenna, x, y, ground)` (rover antenna
  `ROVER_ANTENNA_HEIGHT` = 1 m). Tests add `tests/worldfiles.py`: `sheet`,
  `terrain`, `model_root`, `rock_vertices`, `world_copy(world, rover=(x, y,
  yaw), pitch, lift, sensors)`, `temp_sdf`, `gz_check`.
- **Routes** (`urc/routes.py`): `easy_route` (slope-limited 8-neighbour
  Dijkstra on a 2 m grid of the smoothed terrain), `approach_grades`, `rim`
  (any world can line a hilltop's rim by passing it to `terrain.resample` and
  `scatter_each`).
- **SDF** (`urc/sdf.py`) writes every generated model: worlds, props, the
  rover and the station cameras (`gen_model.py`).

New ground types go into `terrains.TYPES`, new rock colours into
`terrains.ROCKS`. A new reusable shape becomes a `features` dataclass or a
`Heightfield` op, not a loop in a world module.

### A new world

1. Add `sim/urc/missions/<name>.py` with `KEY` and `build(models_dir, worlds_dir, media)`.
2. Register it in `MISSIONS` (URC missions) or `COURSES` (test courses) in `missions/__init__.py`.
3. Run `python sim/gen_worlds.py <name>`.

```python
from .. import features, geo, terrain, terrains
from ..world import Layer, WorldBuilder

KEY = "demo"
FEATURES = [features.Mesa("butte", 30, 40, 12, 8, 10, seed=3),
            features.Wash("wash", [(-90, -20), (0, -30), (90, -40)], depth=1.5, sand_step=30),
            features.Patch("gravel", terrains.GRAVEL, -30, 20, 8),
            features.Ledge("ledge", -60, 40, 0.0, 0.5)]

def build(models_dir, worlds_dir, media):
    hf = features.shape(terrain.Heightfield(256, 513).noise(0.5, 60, seed=1), FEATURES)
    w = WorldBuilder(KEY, "Demo", None, geo.Origin(38.41, -110.79, 1370.0), hf, models_dir, worlds_dir, media,
                     seed=1, name=KEY)
    w.terrain([Layer("regolith"), Layer("caprock", start=4.0)])
    features.dress(w, FEATURES)          # zones and blocks before anything stands on them
    w.rover(0, 0, 0)
    keep = w.keep_clear()
    w.rock_field("rocks", w.scatter(200, (0, 0), 100, (0.05, 0.4), avoid=keep))
    w.rock_field("talus", w.scatter(60, (30, 40), 30, (0.1, 0.5), avoid=keep, min_slope=15))
    w.rock_garden("garden", 20, -60, 10, 6, 0.2, avoid=keep)
    w.shrubs(w.scatter_points(10, (0, 0), 100, avoid=keep))
    return w.write()
```

(Built and checked with `gz sdf -k` on 2026-10-06: 8 zones, 297 rocks, 10 shrubs.)

### Generating

`pixi run sim-worlds` (or `python sim/gen_worlds.py [world ...]`) writes
`worlds/urc_<mission>.{sdf,json}` and `worlds/proving_ground.{sdf,json}` and the
models they use. Generation is deterministic; edit the layouts in
`urc/missions/`, not the output. Its pixi inputs are `gen_worlds.py`,
`gen_model.py`, `urc/**/*.py` and `data/dem/*`.
- At the end of every run, `prune` removes the `urc_*` models and `urc_media`
  files that no `worlds/*.sdf` (or the models those use) references.
- Runs may overlap (agents each regenerating their own worlds): each builds
  under a shared flock on `models/.gen_worlds.lock`, and prune takes it
  exclusively, so it waits for every run still writing. Anything else that
  writes into `sim/models` must hold `gen_worlds.lock(models_dir)`. Building
  the same world twice at once is not supported. Media writes each new file
  under a hidden per-process name and renames it when complete; prune deletes
  partial files left by runs that died.

### Mission sheets

`worlds/<world>.json` is the judges' hand-out plus ground truth:
- `origin` (WGS84 of the world origin), `points` and `objects` with world `x, y,
  z` and WGS84 `lat, lon, alt` (what the rover's GNSS reports), `tasks` with
  rule references, tolerances and points, `c2` with its antenna, `rover_start`,
  `time_limit_s`.
- `terrain`: `heightmap` (16-bit PNG, centred on the world origin, row 0
  north, column 0 west, z = pixel / 65535 × `z_max`), `dem_geotiff` (the same
  surface as a GeoTIFF, so DEM tooling can be practised), `size_m`, `samples`,
  `z_max`.
- `terrain_zones`: {key: type, title, mu, center, area_m2, tiles, tiled_area_m2,
  outline}; `terrain_types`: {type: title, mu, max_slope_deg, notes}; `rocks`:
  {group: count, colliding} (rocks dropped off zones not counted); `shrubs`: the count.
- Per mission: `astronaut` (Autonomy), `lander` (Equipment Servicing),
  `site_radius_m` and `ground_truth_units` (Astrobiology).
- `judges_only`: what the judges would not hand out. Autonomy: `easy_route`
  (with `clearance_m`), `rim`, `approach_grades`, `washes`, `terrain_source`
  (provenance, `edits`, `altitudes`). Delivery: `ridge`, `ridge_pass`, `wash`,
  `steep_mesa`, `boulder_field`, `stony_ground`.

World frame: x east, y north, z up, origin at the **terrain centre and its
lowest point** (Gazebo needs the heightmap there, see Gazebo lessons), so the
C2 station is not at the origin. Layouts are written in metres from C2 (a
course's entrance); `WorldBuilder` converts. Every `alt` is the origin's
altitude plus z: ellipsoidal in Autonomy, NAVD88 in the other worlds (see
Known limitations).

### Referee

`pixi run referee <mission> [--method device|sign|speech|gesture] [--key word] [--seed N]`:

- **Autonomy**: moves the astronaut (`set_pose`) and gives each command by the
  chosen method: `device` → `/astronaut/command`, `speech` → `/astronaut/speech`
  (stands in for audio), `sign` raises the astronaut's sign (ArUco 10; the
  command order is fixed, Q&A Autonomy 13), `gesture` uses one gesture per
  command (beckon for Follow!/Come!, palm out for Stay!, point down for
  Fetch!, both arms out for Give!). Scores per rule 1.e (Follow! by method).
  The astronaut waits at the GNSS point until the rover arrives, so the
  sub-missions can come in either order; each later command times out after
  4 min. Stay! needs the rover with the astronaut and the astronaut > 20 m
  away; for Come! the astronaut first walks to 20 m; Fetch!/Give! need the
  hammer picked up after Fetch! and dropped by the astronaut. Route targets
  need the rover stopped within 1 m and the LED green.
- **Equipment Servicing**: draws a 3–6 letter launch key (printed and on
  `/urc/launch_key`), decodes key presses into the display text
  (`/urc/display`, backspace works), and judges the cache, drawer, panel,
  lock, hose, valve and controls from joint angles and part poses.
- **Delivery**: an object counts as delivered lying on the ground, at rest
  for 1 s, within 2 m of the astronaut; a quarter of the task for opening the
  toolbox or finding a stage-2 object (part of the task's share, not extra).
- **Astrobiology**: a site is a stop of ≥ 30 s, ≥ 20 m from other sites, C2
  and the start, within 0.5 km of C2; then back within 15 m of C2. The science
  is judged by people.

It also publishes `/urc/score` (JSON, 1 Hz) and `/urc/radio` (`los` / `nlos`
between the 3 m C2 antenna and a point 1 m above the ground under the rover,
sampled every 0.5 m along the line, the same test as the sheet's `radio_los`
flags), re-sends the launch key and display text every second, and draws the
LED: the rover's software publishes its state on `/led`, the referee colours
the LED on the rover's back. Where the rules give no points (Equipment
Servicing, Delivery), tasks share 100 points equally; the field judges decide
that at URC. Distances are from the rover's footprint; "stopped" is < 5 cm/s
for 2 s.

## Gazebo lessons (gz-sim 8, this env)

Measured while building the worlds and the station; each cost a wrong first attempt.

- **Heightmaps must sit at the world origin with their lowest point at
  z = 0.** DART collision ignores the heightmap's `<pos>` (and a negative
  `<pos>` z makes objects freeze or fall through), while the ogre2 visual
  ignores the model's pose. Anywhere else, what you see and what you hit
  differ. `urc/world.py` therefore shifts each world so the terrain is there.
- **Gazebo scales image heightmaps by the image's own maximum pixel**, not by
  the format's range: every heightmap spans 0–65535.
- **ogre2 heightmaps blend at most four textures**; extra layers are silently
  dropped.
- **`<friction>` works only on primitive shapes.** Heightmaps and meshes
  always have μ 1.0, and DART takes min(μ_a, μ_b) of two touching shapes in
  each direction: friction zones are box tiles (see above), and ground of
  μ ≤ 0.5 erases the tires' anisotropy.
- **Every shape costs time every step, touched or not**: 0.56–0.83 µs per
  collision shape and 0.10–0.18 µs per visual per 1 ms step (400 extra static
  boxes in the proving ground's terrain link, out of reach). A separate static
  model costs about 2–4 µs (measured on one model per shrub), and its bounding
  box is tested against the heightmap every step: hundreds of separate rocks
  cost 3×. So
  rocks, shrubs, tiles and blocks are shapes of the terrain's own link (a body
  never collides with itself), rocks and shrubs merged per 128 m chunk;
  merged rock collisions are nearly free (Astrobiology ran as fast without
  them). The catch-floor under the terrain is a box, not an infinite plane,
  whose bounding box would overlap everything.
- **NavSat noise is in degrees** for latitude/longitude; `gen_model.py`
  converts metres.
- **The conda gz-rendering has a space-padded OGRE plugin path**: set
  `OGRE2_RESOURCE_PATH` (run.sh, the station and the tests do) or cameras cannot render.
- **On macOS a rendering server must run on the main thread**, and ogre2
  starts once per process: tests strip the Sensors system from world copies
  and render the one camera test in a subprocess.
- **A camera renders only while its topic has subscribers**, and the RGB-D
  camera's first colour image after a time without colour subscribers is all
  black (gz-sensors 8; depth is not affected): the station drops it.
- **Python `gz.transport13` `node.request()` keeps the GIL while it waits.**
  With any subscription active, gz-transport's reception thread blocks on the
  Python callback and the reply can be lost, although the server still acts on
  the request. Measured: with a `/world/<w>/clock` subscription every create
  and pause request timed out; with none, replies came in 0.00–0.11 s. Send
  requests before subscribing, or confirm the effect another way (the station
  watches the camera's state topic).
- **`/world/<w>/stats` comes at 10 Hz wall clock**, also while paused and at
  real-time factor 0.2; `/world/<w>/clock` every step (about 1 kHz).
- **`topic_list()` lists advertised topics only**, not subscribed-only ones.
  After a clean SIGINT stop, a server's topics leave the list at once.
- **DiffDrive has no command timeout**: the last twist stays in force.
- `JointStatePublisher` publishes every 1 ms step here; the lander's 101
  joints use `JointMonitor` (50 Hz, plus an event per key press).

## Troubleshooting

- **Nothing on the topics / GUI shows an empty world:** gz-transport discovery
  can fail without a network (`No route to host`). Run everything, including
  the bridge, with `GZ_IP=127.0.0.1`.
- **`Failed to load system plugin [RockerDifferential]` (or `JointMonitor`, `ChaseCamera`):**
  run through `pixi run sim` or `pixi run drive` (they build the plugins and set
  `GZ_SIM_SYSTEM_PLUGIN_PATH` to `sim/build`).
- **`Unable to load Ogre Plugin`, no camera images:** set
  `OGRE2_RESOURCE_PATH=$CONDA_PREFIX/lib/OGRE-Next` (run.sh does). The error
  is printed once even when the fallback then works.
- **`gen_worlds.py` cannot read `route_area_3dep.tif`:** the DEM is
  git-ignored. Fetch it (`python sim/tools/fetch_dem.py --force`) or, in a git
  worktree, link it (`sim/tools/link_data.sh`).
- **The referee prints "waiting for the simulation":** start or unpause the
  world; the referee needs `/model/rover/ground_truth`.
- **The station exits with "another driver station is attached to …":** use
  that station's page, or stop it first. Two worlds need two partitions
  (`GZ_PARTITION=<name>`).
- **The page says "No picture yet":** the world has no Sensors system, or the
  station's camera models did not spawn (see its console lines); a big world's
  first picture can take a while.
- **The rover keeps driving after a crash:** whatever published `cmd_vel` died
  without sending a zero twist (DiffDrive has no timeout). Publish one, or
  restart the station.
